# Roadmap (P1–P17)

Source: `MASTER_PROMPT.md` §22, decision E3 (owner, 2026-11-26). It replaces the earlier
10-phase roadmap, which is in git history at `55528fd`.

**Rules.** One phase per session. Each phase starts with a plan that the owner approves, and
ends with passing acceptance criteria, a commit and push, a progress update, and owner review.
The next phase never starts without explicit approval. Ordering constraints: P2 before any data
feature, P6 before P7, P12 before production.

Items tagged **(gap)** come from `GAP_ANALYSIS.md` and were assigned to a phase by the owner on
2026-11-26. Estimates were dropped; each phase plan re-estimates its own work.

## Dependencies & critical path

- **P2** needs a Supabase project (EU, Frankfurt), which is an owner credential.
- **P3** needs a Resend domain for invitations and auth emails, plus Google OAuth client
  credentials if Google is to be on.
- **P6** decision gate: the Arabic dialect eval on Haiku decides whether the `standard` profile
  keeps Haiku as the default (A15).
- **P12** needs a PayPal business account and sandbox credentials, with plan ids per environment.
- **P13** needs Meta Business verification, app review and test assets. The lead time can be
  weeks, so start the paperwork during P8. The owner has no commercial registration yet, so
  Embedded Signup stays blocked and manual mode is the workaround.
- **P13 → P14**: P13 ships the minimal admin screen for entering credentials; P14 completes the
  admin panel.
