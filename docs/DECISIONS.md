## B. Approved pricing (USD)

| Plan       | Price        | AI replies / mo | Bots   | Users                   | Channels           | Features                                                                                                                |
| ---------- | ------------ | --------------- | ------ | ----------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| Trial      | free, 7 days | 100 (total)     | 1      | 1 _(assumed — see P12)_ | Widget only        | basic                                                                                                                   |
| Starter    | $39/mo       | 1,000           | 1      | 1                       | Widget + 1 channel | basic analytics; no orders/reservations; no handoff; **hard stop** at limit with upgrade prompt                         |
| Growth     | $99/mo       | 5,000           | 2      | 3                       | all channels       | advanced analytics + question classification, orders/reservations, human handoff; overage **$10 / extra 1,000 replies** |
| Enterprise | from $299/mo | custom          | custom | unlimited               | all                | custom limits, usage-based, multi-branch, API access, manual contracts                                                  |

- Billable unit = **AI-generated reply**. Inbound messages are free (analytics only).
- Annual billing = 2 months free (annual price = 10 × monthly).
- One-time Meta channel connection fee: **$49 per channel** (PayPal one-time checkout **or** manual path). Refundable if the connection cannot be completed.
- Usage alerts at **80 % and 100 %**.
- Plans and limits are data-driven (DB tables), never hardcoded.

## D. Architect proposals awaiting approval

| #   | Proposal                                                                                                                                                                                                                                                                                                                                                                         | Rationale                                                                                                                               | Alternative                                                                                               |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| P1  | **Custom `jobs` table** with `FOR UPDATE SKIP LOCKED` claim function (not pgmq)                                                                                                                                                                                                                                                                                                  | Fully visible in migrations, typed columns (idempotency key, run_at, backoff, workspace_id), easy pgTAP tests, admin dashboards via SQL | Supabase Queues (pgmq) — fewer moving parts we own, less control over schema                              |
| P2  | Worker woken **two ways**: (a) the inbound edge function calls the worker directly in the background right after enqueueing; (b) `pg_cron` + `pg_net` sweep every ~10 s as a safety net                                                                                                                                                                                          | Low latency for the hot path, guaranteed eventual pickup                                                                                | Cron-only (simpler, slower)                                                                               |
| P3  | Dashboard reads through **supabase-js + RLS**; any write with business rules (billing, invitations, channel requests, sending messages, uploads) goes through Edge Functions                                                                                                                                                                                                     | Less API surface to build; RLS is the security boundary                                                                                 | Everything through a REST API (more code, same security)                                                  |
| P4  | Plan limits enforced **inside Postgres** (triggers + `consume_ai_reply()` RPC), not only in app code                                                                                                                                                                                                                                                                             | Limits hold regardless of the call path; race-safe                                                                                      | App-layer only (bypassable, racy)                                                                         |
| P5  | Channel credentials (Meta tokens) stored in **Supabase Vault**, referenced by id                                                                                                                                                                                                                                                                                                 | Encrypted at rest, never selectable through PostgREST                                                                                   | App-level encryption with a KMS key                                                                       |
| P6  | Widget realtime: server sends a **content-free "new message" ping** over Supabase Realtime Broadcast on an unguessable topic; widget then fetches over the authenticated widget API. Polling fallback                                                                                                                                                                            | No message content on a public channel                                                                                                  | Anonymous Supabase sign-ins + RLS on `messages`                                                           |
| P7  | Super Admin panel lives **inside `apps/dashboard`** under `/admin` (lazy-loaded chunk, separate route guard)                                                                                                                                                                                                                                                                     | Approved monorepo layout has no `apps/admin`                                                                                            | Separate `apps/admin` app (stronger isolation)                                                            |
| P8  | Widget built with **Preact** (React-compatible API) inside a Shadow DOM, target ≤ 35 kB gzip                                                                                                                                                                                                                                                                                     | Third-party script size and CSS isolation matter on customer sites                                                                      | React (≈ 45 kB+ gzip runtime alone)                                                                       |
| P9  | Default generation model **`claude-opus-5-5`** at `low` effort, configurable per plan in the DB (`ai_model_profiles`). **⚠ Estimated cost ≈ $18 / 1,000 replies → ~90 % of Growth revenue at full use, and overage ($10 / 1,000) would be sold below cost** (`AI_ENGINE.md §9`). Owner must choose: re-price, or a different profile per plan, after Phase 04 measures real cost | Highest quality for Arabic dialects                                                                                                     | `balanced` (`claude-sonnet-5-5`, ≈ $9 / 1k) or `economy` (`claude-haiku-5-5`, ≈ $0.7 / 1k) for some plans |
